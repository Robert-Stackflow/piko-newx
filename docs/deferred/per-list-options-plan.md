# 每个列表独立显示配置：实施计划

状态：已搁置，尚未实现。用户于 2026-09-12 要求暂停此功能、先整理现有代码。本文仅保留设计记录，不属于当前交付范围或执行指令。

## 目标与基线

在“所有列表的默认配置”之上，为每个账号下的每张列表增加覆盖配置：转推、回复、引用帖、关键词。未设置覆盖时，保持升级前行为。

当前开发分支已 rebase 到 piko-newx 构建仓库 v3.19.3；中文/自定义补丁源码仍固定为 Piko bc03fce4352bcb7ee89299722d0e900af3fb8a82，目标 X 12.22.0-prod.01。此次功能开发先沿用这一已测基线，不把升级补丁源码、修改位置恢复算法和增加功能混成一次交付。将来升级需要重新验证绑定。

## 已核实的限制

- HomeTimelineOptionsPatch 在 Success 构造入口调用 TimelineRepostFilter.filter(items, timelineEnum)。这里只传时间线类型，不能区分账号与具体列表。
- PostFilterPatch 在同一个构造入口调用全局 filterPostsByKeyword(items)，没有传时间线身份。事后添加本列表过滤不能找回已被全局规则删除的显示项。
- ListPositionUiHooks 已解析原生组件上的账号 owner、仓库 TimelineIdentifier 与状态流；可复用解析思路，但身份绑定不能依赖“恢复列表阅读位置”开关。
- NewX 设置支持 customScreen 和扩展拥有的 Fragment；不需要把可变数量的列表逐条注册为固定设置项。
- 原生文本/回复元数据有现成适配器可供审查；引用帖准确分类的字段契约仍待目标 DEX 验证，不能靠正文包含链接或 RT 字样判断。

## 用户入口

Piko NewX 设置 → 时间线 → 列表独立配置。

页面显示当前账号、列表默认配置、已识别列表。每个列表显示名称及“跟随默认 / 已自定义”摘要，同名列表显示额外身份提示。列表名称仅为展示，不作为存储键。

优先收集当前账号已加载的首页固定列表，以及实际打开过的列表；不为设置页面新增后台请求。首次尚无数据时提示“先打开一次列表”。非首页固定列表也按相同 ID 使用配置。改名不丢配置；取消固定不删除配置；提供重置单列表覆盖。

列表标题/账号绑定的采集路径需要验证。采集身份不能用一个全局“当前选中列表”变量，也不能仅从列表标题推断账号。

第一版不增加标签长按菜单，不改变标签点击/回顶语义。

## 配置语义

| 项目 | 列表默认配置 | 单列表覆盖 |
| --- | --- | --- |
| 转推 | 沿用现有“列表：展示转推”键和值 | 跟随默认 / 展示 / 隐藏 |
| 回复 | 新增，默认展示 | 跟随默认 / 展示 / 隐藏 |
| 引用帖 | 新增，默认展示 | 跟随默认 / 展示 / 隐藏 |
| 关键词 | 沿用现有全局关键词开关与规则 | 跟随全局 / 全局加本列表 / 仅本列表 / 不按关键词过滤 |

明确显示每项当前生效值及其来源。“展示”只取消本功能对应类型的隐藏，不绕过其他独立规则、X 服务端权限、屏蔽或广告过滤。多项规则按交集生效：允许转推但隐藏引用帖时，带引用的转推仍可因引用规则隐藏。

关键词沿用现有短语/用户名匹配器，不新增正则表达式。局部规则与全局规则分开保存；全局关闭时，“全局加本列表”仍执行已启用的本列表规则。第一版正文匹配只针对当前发布者的帖子正文，不递归匹配被引用正文；界面说明这一点。

回复按真实 replied-to 元数据判断，包含作者自回复，不把引用误判为回复。引用按外层帖子的引用关系判断，无法确认的模型保留展示。普通转推按 socialContext 识别。隐藏某行时保留剩余线程结构并同步关联 ID；空模块移除，不能遗留空壳或损坏不可变集合类型。

## 身份与持久化

- 身份键：schemaVersion + accountId + nativeListId；每项覆盖显式区分 INHERIT 与具体值。
- 同一列表在不同账号下隔离；列表改名不改变身份。同账号从首页标签和列表详情进入，配置一致。
- ScopeResolver 独立于位置恢复、转推开关及页面是否可见。从实际数据所属组件/仓库传递不可变 scope，异步返回不能读取另一标签的身份。
- ListOptionsStore 保存带版本的配置及规则，内存提供不可变快照。过滤一批数据时只取一次配置；逐帖不得读磁盘、取 UI 状态或遍历所有列表。
- 名称缓存有容量上限，显式配置不因缓存淘汰而丢失。未知 schema/损坏字段回退默认，不导致整页为空。
- 本地设置备份需要接入新结构；导入先完整校验、再发布，保留账号隔离，旧备份不清空不存在的新字段。导出仅含设置/列表标识，不含令牌、登录凭据或帖子正文，并提示文件包含列表信息。

## 过滤管线：先证明归属，再动入口

1. 在固定目标 DEX 中，从有账号/列表身份的组件追踪到时间线成功状态的生产和消费路径，核实缓存、预加载、分页、详情页及异步路径。
2. 选择已知数据归属、尚未不可逆删除显示项的非 Compose 构建入口。显式传入 scope、原始显示集合及配置快照；不能用 ThreadLocal 跨协程传身份，也不能通过复用集合对象地址猜所属列表。
3. 将 LIST_POSTS 的关键词与自定义转推处理路由到统一 scoped 管线；其他时间线保留原处理。不能同时执行全局关键词删除再执行“仅本列表/关闭”配置。
4. 保持广告、推荐模块、其他上游过滤器的独立语义和执行契约。若无法证明 scoped 路径覆盖，构建失败，不能静默取消全局过滤。运行时未知 scope 保持原有全局关键词与列表默认行为。
5. 同一个显示集合只做一次本功能的递归处理，不改仓库缓存、网络请求、游标、数据库或原始集合。关闭规则后从原生数据重新生成显示结果，不缓存/插回旧帖子。
6. 带配置版本的结果不能跨账号/列表复用；禁止在 Compose provider 构建回调里读取布局快照、触发滚动或写设置，避免重演列表切换 ANR。

上述入口目前是实现前置证明，不是已经验证的现成 hook。若不能证明全局过滤旁路与 fallback 的等价性，先停在验证阶段，不能发布只有界面却语义失效的开关。

## 生效与位置恢复

第一版选择稳定的生效契约：保存后提示重启应用生效，提供用户主动选择的重启按钮，不自动杀进程。尚未应用的配置与当前运行的快照分开，避免“旧画面新规则、后台新数据另一套规则”。全局相关设置变更也要遵循这一契约。

暂不承诺即时重绘。重启后用新规则生成最终显示项，再由现有身份位置恢复验证目标：目标仍存在且唯一才恢复；被新规则过滤后不回退旧序号、不补回旧帖。不自动清空该账号其他列表的阅读位置。

## 交付步骤与关卡

1. **身份与入口验证**：审查确切 DEX、解析 scope/列表名称/引用关系；建立 fail-closed 匹配和旧行为对照。只记录脱敏身份及规则版本。
2. **策略与存储**：实现独立 scope、三态覆盖、关键词四种模式、迁移及备份验证；先跑纯逻辑测试。
3. **设置界面**：实现列表选择页与详情编辑页，显示继承结果、重置入口及重启提示；完成中英文文本和占位符校验。
4. **过滤接入**：先接转推，完成账号/列表隔离验收；再接回复、引用和关键词。阶段性构建不冒充完整功能。
5. **集成与真机**：检查最终 DEX、ART 类初始化、集合返回类型、签名与对齐，再覆盖安装；保留 listfix.6.2 和 listfix.5 回退包，不清数据。

新增源码/资源时同步更新 apply_fixes.py 的文件清单约束、构建版本、单测与最终 DEX 验证工具，不放宽成“任意数量都通过”。绑定必须使用语义/类型/字段关系，不把当前混淆名写成生产常量。

## 验收清单

- 未设覆盖时，与旧版本默认行为一致；全局默认变化只影响继承项。
- A 列表隐藏转推、B 展示；来回切换、预加载与延迟响应不串规则。
- 同名不同 ID、同 ID 不同账号、改名、取消固定、从详情进入及重启均正确。
- 位置恢复开关关闭后，列表配置仍可识别并生效。
- 普通帖/转推/回复/引用及组合、空/未知模型、线程和嵌套模块；其他时间线不受影响。
- 关键词继承/叠加/替换/关闭四模式均与说明一致，尤其全局隐藏的词能在“关闭关键词过滤”的列表正常展示（无其他规则阻止时）。
- 未改规则前后的原始集合、仓库数据、游标和分页不变；全被过滤时不无限自动翻页。
- 修改规则隐藏当前锚点后不跳入另一列表、不补旧帖；快速切换无 ANR/闪退。
- 配置保存/取消/重置/重启、旧配置迁移、备份导入失败的原子性和错误恢复。
- 真机查看内容/互动需与用户协调；不发帖、点赞、转推、关注或上传设备诊断/正文。

## 第一版明确不做

自动拉取账号的全部列表、跨账号同步、逐列表专属广告策略、关键词正则、引用正文递归匹配、即时重绘、改写数据层保位，以及升级 X/Piko 补丁基线。
